# 収益化戦略 & Claude自動開発ステップアップ計画

作成日: 2026-07-09
目標: **2027年3月までに広告収益の仕組みを完成させ、不労所得月1万円の土台を作る**

---

## 1. 現状分析

### 強み
- Notion CMS による記事更新の自動性（既に構築済み）
- ツール・ゲームの実装基盤（features/ 構造、/add-feature フロー）
- YouTube（FFTバトル動画）という外部集客チャネルの種がある
- Vitest / Storybook / ESLint の開発基盤が整っており、Claude による自動開発と相性が良い

### 弱点（収益化のブロッカー）
| 問題 | 影響 |
|------|------|
| Vercel Hobby プランは商用利用（広告）不可 | **広告を貼った時点で規約違反** |
| 独自ドメインなし | AdSense は `*.vercel.app` 等のサブドメインで申請不可 |
| Google インデックス未登録・SEO未対応 | 検索流入ゼロ = 収益ゼロ |
| プライバシーポリシー・免責ページなし | AdSense 審査で必須 |
| ホームページ（index.tsx）未完成 | 審査・回遊率の両方に悪影響 |
| OGP がSNSで表示されない（MEMO.md） | SNS/YouTube からの流入導線が弱い |

### 著作権・API規約リスク（広告と併載できないもの）
- **マンガ表紙画像**: 著作権グレー（MEMO.md 自認）。広告ページに載せると AdSense ポリシー違反リスク
- **Spotify 検索**: Developer Policy 上、Spotify コンテンツへの広告併載は制限あり
- **AniList のカバー画像**: 出版社著作物

→ **結論: サイトを「広告ゾーン」と「非広告ゾーン」に分離する**

## 2. 収益構造の設計

### 公開範囲の絞り込み（ゾーニング）

```
【広告ゾーン】収益の主戦場。オリジナルコンテンツのみ
  /                     ホーム（完成させる）
  /article/*            記事（Notion連携済み）
  /gallery/tool/*       ツール群 ← SEO集客の主力
  /gallery/game/*       ミニゲーム
  /fft/*                FFT動画連携ページ（新設）← 独自性の核

【非広告ゾーン】広告タグを入れない。noindex も検討
  /search/music         Spotify
  /search/manganime     AniList
  /gallery/manga        マンガ表紙
```

実装イメージ: `_app.tsx` でルートベースの広告表示制御（広告ゾーンの
ホワイトリストを持つ）。ページ単位の判断ミスを構造で防ぐ。

### 収益源ポートフォリオ（着手順）

| 収益源 | 審査 | 単価 | 着手タイミング |
|--------|------|------|---------------|
| 楽天アフィリエイト | なし（即日） | 料率2〜4% | Phase 1（マンガ・書籍紹介記事に） |
| Google AdSense | あり（記事10本+・独自ドメイン必須） | 約0.2〜0.5円/PV | Phase 3 |
| Amazonアソシエイト | あり（180日以内に3件成約） | 料率2〜8% | Phase 3（AdSense後） |
| 忍者AdMax | ほぼなし | AdSenseより低単価 | AdSense不合格時の保険 |

**現実の数字**: ディスプレイ広告で月1万円 ≒ 月2〜5万PV が必要。
個人サイトが1年でここに届くのは難しいため、**「AdSense（薄く広く）+
アフィリエイト（記事単位で深く）」の複合**で設計する。

### PVマイルストーン
- 2026-09: 月1,000PV（ツール検索流入の芽）
- 2026-11: 月5,000PV + AdSense合格
- 2027-03: 月15,000PV + アフィリエイト成約 → 月数千円
- 月1万円は2027年後半の継続目標（就職後も自動運転で伸ばす）

## 3. 集客戦略

### 柱1: 単機能SEOツール（検索流入）

キーワードが明確で、個人サイトでも上位を狙える領域。MEMO.md のアイデアから選抜:

1. **文字化け修正ツール**（二重文字化け対応）
   - 「文字化け 直す」「文字化け 変換」は定番の実用検索。競合ツールはUIが古いものが多く、UXで差別化可能
2. **LINE風トーク画面ジェネレーター**
   - 「LINE 画像 作成」系は検索需要が大きい。SNSでシェアされやすく二次拡散も狙える
3. **ES文字数カウンター（既存）の強化 + 使い方記事**
   - 就活シーズン（10月〜）に向けて9月までに記事とOGPを整備
4. （余力があれば）画像・動画圧縮ツール — 「無料 画像 圧縮」は激戦区だが needs は無限

**各ツールに必ず「使い方・解説記事」を1本セットで付ける。**
ツール単体ページは AdSense 審査で「コンテンツ不足」と判定されやすい。
記事はNotionで書けるので更新コストは低い。

### 柱2: YouTube × FFT 連携（独自コンテンツ + 導線）

SFTリポジトリの `fixtures.json` / `weapons/` / `WEAPONS.md` を資産として活用:

1. **キャラ・武器図鑑ページ** `/fft/characters`, `/fft/weapons`
   - SFTのデータファイルからビルド時に静的生成 → 更新は自動
2. **対戦成績データベース** `/fft/records`
   - 試合結果の蓄積 → 「このキャラの勝率は?」という動画視聴者の再訪動機になる
3. **動画一覧ページ**（YouTube Data APIで自動取得）
4. **YouTube概要欄 → サイトへのリンク**を全動画に設置
   - 逆にサイトから動画への埋め込みも行い、相互送客する

これは「他のどこにもないオリジナルコンテンツ」なので AdSense 審査でも強い。
開発リポジトリの紹介は GitHub リンク + 技術解説記事にすると B5（技術発信）とも接続する。

### 柱3: 基礎SEO（全ページ共通）

- sitemap.xml / robots.txt 生成（next-sitemap）
- Search Console 登録 + インデックス申請
- OGP修正（LINE等で画像が出ない問題 → 絶対URL・og:image サイズ確認）
- 記事・ツールページの title / description をキーワード設計し直す

## 5. Claude 自動開発ステップアップ（5段階）

「自分がどこまで手を離せるか」を段階的に引き上げる訓練計画。
各Phaseの開発を、対応するStepの手法で実施することで習熟する。

### Step 1: 対話開発（現在地）
- Claude Code と対話しながら実装。全変更を目視レビュー
- **対象**: Phase 0 の土台整備（規約・SEO周りは判断が必要なので対話向き）

### Step 2: スペック駆動の一括実装
- `docs/ideas/` にアイデア → `/add-feature` で実装を自動化
- `.steering/` にタスクリストと振り返りが残る既存フローをフル活用
- **対象**: Phase 1 のツール群（既存パターンの複製なので自動化しやすい）
- **習熟目標**: 「アイデアメモを書けばツールが1本できる」状態

### Step 3: 並列・バックグラウンド開発
- git worktree + サブエージェントで複数機能を同時進行
- 例: 文字化けツールとLINE風ジェネレーターを並列で実装させ、レビューだけ自分で行う
- **対象**: Phase 1 後半〜Phase 2
- **習熟目標**: 「自分はレビュアーに徹する」状態

### Step 4: CI連携・ヘッドレス実行
- GitHub Actions + `claude -p`（ヘッドレスモード）で Issue 駆動開発
  - Issue にラベルを付けたら Claude が実装 → PR 作成 → 自分はマージ判断のみ
- lint / test / build を通過しないと PR が作れないガードレールを整備
- **対象**: Phase 2〜3 の定型的な機能追加・修正
- **習熟目標**: 「Issueを書けばPRが届く」状態

### Step 5: 定期自動運用（危険期間の生命線）
- スケジュール実行される Claude エージェントで運用タスクを無人化:
  - SFT の fixtures 更新 → 図鑑・成績ページの自動再ビルド
  - YouTube 新着動画 → 動画一覧の自動更新 + 紹介記事の下書きをNotionに生成
  - 週次: リンク切れ・ビルド健全性・Search Console 指標のチェックレポート
- **対象**: Phase 3 で構築し、Phase 4（12〜2月）に本番運用
- **習熟目標**: 「見ていなくてもサイトが更新され続ける」状態

## 6. やらないことリスト（スコープ防衛）

- App Router 移行（収益に寄与しない）
- 認証基盤・ログイン機能（reCAPTCHA等はPhase 4以降に再検討）
- マンガ検索・音楽検索の機能拡張（非広告ゾーンなので投資対効果が低い）
- 投票サイトの本格展開（集客が読めない。既存機能の維持のみ）
- ES添削コミュニティ等の双方向サービス（運用コストが危険期間と相性最悪）
