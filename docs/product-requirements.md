# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**Haruhate** - 個人ポートフォリオ・クリエイティブツールサイト

### プロダクトコンセプト
- **自己表現の場**: 技術記事・ギャラリー・制作物を通じて、作者の関心・スキルを発信する
- **実用ツール集**: 就活・趣味・創作活動で実際に役立つWebツールを自作して公開する
- **技術探求の記録**: 実装して初めてわかることを形にしながら、技術的な成長を可視化する

### プロダクトビジョン
個人開発者 TaiyoNawa が「作りたいものを作る」という姿勢で運営する個人サイト。
記事・ゲーム・ツール・音楽など多ジャンルのコンテンツを1サイトに集約し、訪問者が「また来たい」と思えるコンテンツの多様性と、作者自身が日常的に使いたくなるツールの実用性を両立する。
就職活動においては、実装力・設計力・継続性を示すポートフォリオとしても機能させる。

### 目的
- 技術的な興味・成果物をまとめて発信できる場を持つ
- 自分が実際に使う便利ツールを自作・公開することで実装スキルを磨く
- GitHubポートフォリオとして就活・転職時に参照できる実績を積む

- ES作成時に文字数カウントツールを使いたい就活生

## 成功指標 (KPI)

- **公開ツール数**: 5本以上（2026年末時点）※現在2本（es-counter, poll）
- **公開記事数**: 20本以上（累計、Notion連携）

- **Core Web Vitals（LCP）**: 2.5秒以内（主要ページ）
- **テストカバレッジ**: utils / hooks 層は 80% 以上を維持

### P0（必須・次に実装）

#### ChordRunner — ギターコードチェンジ練習ツール

**ユーザーストーリー**:
ギター初心者として、コードチェンジの反復練習を視覚的・聴覚的にサポートしてほしいので、次のコードをゴーストで先行表示しながらBPMに合わせて自動進行するWebアプリが欲しい。

**受け入れ条件**:
- [ ] コード進行をUI上でクリック操作のみで組み立てられる
- [ ] ギター指板上に現在コードの運指（黒）と次コードの運指（透過グレー）が同時表示される
- [ ] 現在・次コードで押さえ位置が重なる場合も視認できるUIになっている（枠線表示等）
- [ ] BPMをスライダーまたは数値入力で設定できる（推奨範囲: 40〜200）
- [ ] 再生するとメトロノーム音が鳴り、設定した拍数ごとに次のコードへ自動遷移する
- [ ] コードの和音音声が拍頭で再生される（事前収録サンプル音源を Tone.js 等でスケジュール再生）
- [ ] 収録コード: C, G, D, A, E, Am, Dm, Em, F, Bm（最低10種）
- [ ] コード進行は無限ループで練習できる
- [ ] `/gallery/tool/chord-runner` でアクセスでき、ギャラリーツール一覧から導線がある

**優先度**: P0（必須）

---

### P1（重要・ChordRunner後に着手）

#### flowmusic — AIプロンプト集（音楽生成ショーケース）

**ユーザーストーリー**:
作者として、n8n + Flow Music で自動生成した楽曲とYouTube動画を自サイトに自動掲載したいので、Supabaseからデータを取得して表示するAIプロンプト集ページが欲しい。

**受け入れ条件**:
- [ ] Supabase（クラウド）の `music_prompts` テーブルから `status=completed` のレコードを取得できる
- [ ] 各楽曲にYouTube埋め込みプレイヤー・プロンプトテキスト・生成日時が表示される
- [ ] `getStaticProps` + ISR（revalidate: 3600）でビルド時取得・1時間ごと自動更新される
- [ ] `/gallery/prompt/flow-music` でアクセスでき、ギャラリー一覧から導線がある
- [ ] Supabase APIキーは `.env.local` で管理し、クライアント側に露出しない設計になっている

**優先度**: P1（重要）

#### ChordRunner 拡張: セブンス・sus4 コード追加

**ユーザーストーリー**:
ギター中級者として、基本コードを習得した後により多彩な進行を練習したいので、G7・C7・Dsus4 などの装飾コードが収録されているほしい。

**受け入れ条件**:
- [ ] セブンス系（G7, C7, D7, A7, E7, Am7）が追加されている
- [ ] sus4 系（Gsus4, Dsus4）が追加されている
- [ ] 既存の指板UIと同じ方式で表示される

**優先度**: P1

## 非機能要件

### パフォーマンス
- ページ初期表示（LCP）: 主要ページで 2.5秒以内
- ギャラリーツール（ChordRunner 等）: 操作レスポンス 100ms 以内（音声再生遅延含む）
- ISR ページ: revalidate 設定により API 呼び出しを最小化し、Notion / Supabase レート制限に抵触しない

### ユーザビリティ
- 新規訪問者がツールの基本操作を3分以内に把握できる（説明テキスト・プレースホルダーで補助）
- モバイル（375px〜）・タブレット・デスクトップの3ブレークポイントで崩れなく表示される
- Chakra UI のアクセシビリティ基準（aria-label、キーボード操作）を維持する

### 信頼性・デプロイ
- `yarn build` が常にクリーンに通ること（ESLint Error ゼロ・型エラーゼロ）
- Vercel への自動デプロイが main ブランチへのマージで成功すること
- 外部API（Notion・Supabase）障害時はエラー画面でなくフォールバック表示を行う

### セキュリティ
- APIキー・シークレットは `.env.local` で管理し、クライアントバンドルに含めない
- 問い合わせフォームはサーバーサイドでバリデーションを行う
- `.env` ファイルは Git にコミットしない（`.gitignore` 管理済み）

### 保守性
- `features/` 単位でコンポーネント・hooks・utils・型を同梱し、機能間の依存を最小化する
- utils / hooks 層のテストカバレッジ 80% 以上を維持する
- Storybook でコンポーネントのビジュアル仕様を文書化する
